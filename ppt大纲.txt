三、项目背景与目标（第 3~4 页）
========================================================================

【第 3 页：项目背景】
- 手写数字识别是图像分类领域的经典问题
- 验证码（CAPTCHA）是区分人机的常见手段
- 用 CNN 解决这两个问题可验证深度学习在图像识别中的有效性
- 本项目旨在构建一个完整可演示的 AI 应用系统

【第 4 页：项目目标】
- 训练一个优化的 CNN 模型识别 0-9 手写数字（准确率 > 99%）
- 构建基于浏览器的画板交互界面
- 实现四连数字验证码的自动合成与 CNN 识别
- 构建完整的验证码登录系统（Web + 桌面）
- 将 CNN 识别结果可视化展示在前端界面

五、模块一：手写数字识别（第 6~8 页）
========================================================================

【第 6 页：模型结构】
- 数据集：MNIST（28×28 灰度图，10 个类别）
- 图像预处理：灰度化 → 28×28 → [0,1] 归一化 → 反色
- CNN 结构：
  第1层：Conv2D(32, 3×3) + BatchNorm + MaxPool + Dropout
  第2层：Conv2D(64, 3×3) + BatchNorm + MaxPool + Dropout
  第3层：Conv2D(128, 3×3) + BatchNorm
  第4层：Conv2D(256, 3×3) + BatchNorm + MaxPool + Dropout
  Flatten → Dense(128) → Dropout(0.5) → Dense(10) + Softmax
- 优化器：Adam
- 总参数量：约 XX 万（放 model.summary() 截图）

【第 7 页：训练流程与优化】
- 数据划分：train/val/test (80%/10%/10%)
- 数据增强（ImageDataGenerator）：
  - 旋转范围：±12°
  - 平移范围：±12%
  - 缩放范围：±12%
- 训练回调：
  - EarlyStopping（patience=8，监控 val_accuracy）
  - ModelCheckpoint（保存最佳模型）
  - ReduceLROnPlateau（学习率衰减）
- 训练结果：
  - 测试集准确率：~99.2%（放训练曲线图）
  - 混淆矩阵分析（哪些数字容易混淆，如 4↔9、3↔8）

【第 8 页：Web 界面】
- 框架：Gradio
- 功能：
  - 左侧：画板（画笔书写 + 清空按钮）
  - 右侧：识别结果（预测数字 + 概率条形图）

六、模块二：验证码登录系统（第 9~14 页）
========================================================================

【第 9 页：验证码生成流程】
- 从 MNIST 数据集中随机抽取 4 个数字图片
- 拼合为 28×112 的四连数字图
- 数据增强（重点）：
  参数            | 增强范围
  ───────────────┼───────────
  旋转角           | ±30°
  高斯模糊         | σ：1.0 ~ 2.5
  高斯噪声         | σ：0.05 ~ 0.15
  对比度变化       | 0.55 ~ 1.55
  亮度偏移         | ±0.25
  随机膨胀/腐蚀     | 30% 概率
- 训练数据：24,000 张训练 + 4,000 张测试

【第 10 页：验证码 CNN 模型】
- CNN 结构（多分类头设计）：
  Conv2D(32) → Conv2D(64) → Conv2D(128)
  → Flatten → 4 个独立全连接头（每个 10 类）
  → 4 路 Softmax 输出（分别预测第 1/2/3/4 位数字）
- 训练配置：
  - 损失函数：4 路 CategoricalCrossentropy 之和
  - 数据增强更激进（rotation±25°, shift±20%, zoom±18%）
- 训练结果：
  - 验证准确率：~94%+
  - 4 个数字位分别准确率分布（4 位全对准确率）

【第 11 页：验证码系统的两种运行模式】

模式一：CNN 合成模式（USE_ML_CAPTCHA=1）
- 使用 MNIST 合成 + 数据增强生成验证码
- 模型直接在合成数据上训练 → 识别率高

模式二：PIL 增强模式（默认）
- 使用 PIL 绘制带干扰的彩色验证码（现已去掉波纹扭曲）
- CNN 模型推理时对整张验证码图进行识别
- 验证码图片更接近真实场景

【第 12 页：Web 验证码登录流程】
- 流程图：
  用户打开页面 → 请求 /api/captcha-challenge
  → 后端生成 4 张验证码图
  → CNN 模型逐张识别（返回 predictions 数组）
  → 前端展示 2×2 网格 + 每张图下方 "CNN识别: XXXX"
  → 用户选中一张 → 提交验证 → 返回登录结果

- API 响应格式：
  {
    "session_id": "...",
    "images": ["data:image/png;base64,...", ...],
    "predictions": ["4392", "9888", "5934", "3802"],
    "target_code": "3802"
  }

【第 13 页：前端界面设计】
- 技术：原生 HTML + CSS + JavaScript（无框架）
- 布局：
  - 顶部：标题栏 + 用户图标
  - 中间：2×2 验证码网格
  - 底部：验证码输入框 + 登录按钮
- 交互流程截图

【第 14 页：桌面端验证码登录】
- 框架：Python Tkinter
- 功能：
  - 展示 28×112 灰度验证码图片
  - 输入 4 位数字 → 点击登录
  - 显示 CNN 识别结果（供参考，不影响登录判断）
  - 默认模式：输入与正确答案一致即通过
  - 可选模式：输入必须与 CNN 结果一致（CAPTCHA_VERIFY="model"）

七、关键技术对比与难点（第 15~16 页）
========================================================================

【第 15 页：两个模块对比】
对比维度        | 手写数字识别       | 验证码登录
───────────────┼──────────────────┼───────────────────
输入            | 单数字 28×28      | 四连数字 28×112
输出            | 1 个类别（0~9）   | 4 个类别（每位 0~9）
模型            | 单头 Softmax      | 4 头并行 Softmax
界面            | Gradio (自动生成) | 手写 HTML/Tkinter
数据增强        | 标准增强           | 激进增强（模拟模糊）
前端识别展示     | 无（结果即输出）   | 4 张图片下方各标识别结果

【第 16 页：技术难点与解决方案】
- 难点1：训练集与验证码图像域不匹配
  → 方案：增强合成数据集的扭曲参数（旋转、模糊、噪声、对比度）
- 难点2：模型在 PIL 扭曲验证码上识别率低
  → 方案：去掉非线性波纹扭曲，保持字符几何完整性
- 难点3：如何在前端实时展示 CNN 识别结果
  → 方案：后端 API 返回 predictions 数组，前端动态渲染
- 难点4：Tkinter 界面中文乱码
  → 方案：编码处理 + 字体配置
